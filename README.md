# Cutielook Digicam – ระบบบริหารร้านเช่ากล้อง

เว็บ Backend สำหรับเจ้าของร้านคนเดียว ใช้ได้ทั้งมือถือ / แท็บเล็ต / คอมพิวเตอร์ ข้อมูลชุดเดียวกันทุกเครื่อง
(HTML + Tailwind + JavaScript ล้วน + Supabase)

## ขั้นตอนติดตั้ง (ทำครั้งเดียว ประมาณ 10 นาที)

### 1) ตั้งค่าฐานข้อมูลใน Supabase
1. เข้า Supabase > โปรเจกต์ของคุณ > **SQL Editor** > New query
2. เปิดไฟล์ `database/schema.sql` คัดลอกทั้งหมดไปวาง กด **Run**
3. ทำแบบเดียวกันกับ `database/policies.sql` แล้วตามด้วย `database/seed.sql`
   (ทั้ง 3 ไฟล์รันซ้ำได้ ไม่พัง แม้เคยรันของเดิมมาแล้ว)

### 2) สร้างบัญชีเจ้าของร้าน และปิดการสมัคร
1. Authentication > Users > **Add user** > ใส่อีเมล + รหัสผ่าน (ติ๊ก Auto Confirm)
2. Authentication > Sign In / Providers > Email > **ปิด "Allow new users to sign up"**
   (สำคัญ: ไม่งั้นคนอื่นสมัครแล้วเห็นข้อมูลร้านได้)

### 3) ใส่ค่า Supabase
`js/config.js` มี URL และ **anon key** อยู่แล้ว (anon key เปิดเผยได้ เพราะมี RLS คุมอยู่)
ห้ามใส่ `service_role` key ในโปรเจกต์นี้เด็ดขาด

### 4) ทดลองบนเครื่อง
เปิดโฟลเดอร์ด้วย VS Code > ติดตั้ง Live Server > คลิกขวา `index.html` > Open with Live Server
(ต้องเปิดผ่านเซิร์ฟเวอร์ ดับเบิลคลิกไฟล์ตรง ๆ จะไม่ทำงาน เพราะใช้ ES Modules)

### 5) ขึ้นออนไลน์ด้วย GitHub Pages (ฟรี)
1. สร้าง repo ใหม่บน GitHub (แนะนำ Private) แล้วอัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้
2. Settings > Pages > Source: Deploy from a branch > `main` / `(root)` > Save
3. รอ 1-2 นาที จะได้ลิงก์ `https://ชื่อคุณ.github.io/ชื่อrepo/` เปิดจากเครื่องไหนก็ได้
4. Supabase > Authentication > URL Configuration > ใส่ลิงก์นี้ใน Site URL

## ลำดับการใช้งานประจำวัน
Login → Dashboard → ปฏิทิน/ตรวจกล้องว่าง → สร้างรายการเช่า (เลือก/เพิ่มลูกค้า, เลือกกล้อง) →
รับเงิน (เมนูการชำระเงิน) → เปลี่ยนสถานะ จอง→เตรียม→พร้อม→เช่าอยู่→คืนแล้ว →
คืนมัดจำ (เมนูเงินมัดจำ) → ปิดรายการ → ดูรายงาน

## หน้าที่ของไฟล์
| ไฟล์/โฟลเดอร์ | หน้าที่ |
|---|---|
| `index.html` | หน้าหลัก + หน้า Login |
| `js/config.js` | URL/anon key ของ Supabase + สีธีม Tailwind |
| `js/app.js` | ควบคุม Login และสลับหน้า |
| `services/` | เชื่อม Supabase และระบบ Login |
| `repositories/` | ฟังก์ชันอ่าน/เขียนฐานข้อมูลแต่ละตาราง (หน้าเว็บไม่เรียก DB ตรง) |
| `pages/` | หน้าจอแต่ละเมนู |
| `components/` | ส่วนประกอบใช้ซ้ำ: เมนู, toast แจ้งเตือน, modal, ตาราง, ป้ายสถานะ |
| `utils/` | วันที่, เงิน, ตรวจข้อมูล (validation), จัดรูปแบบ/ดาวน์โหลดไฟล์, `shipping.js` (คำนวณระยะทาง/วันส่งตามจังหวัด) |
| `database/schema.sql` | สร้างตาราง + **trigger กันคิวชนที่ฐานข้อมูล** + ฟังก์ชันสร้างรายการเช่าแบบ atomic |
| `database/policies.sql` | Row Level Security: ต้อง Login เท่านั้น |
| `database/seed.sql` | ค่าตั้งต้น (ไม่มีข้อมูลปลอม) |

## กติกาสำคัญของระบบ
- **กันคิวชน 2 ชั้น**: เช็กที่หน้าเว็บ + trigger ที่ฐานข้อมูล (จองซ้อนไม่ได้แม้เว็บมีบั๊ก) รวม Buffer Day ในหน้าตั้งค่า
- CANCELLED / RETURNED / CLOSED ไม่บล็อกกล้อง
- **เงินมัดจำไม่นับเป็นรายได้** รายได้ = ค่าเช่า − ส่วนลด + ค่าปรับ + ค่าส่ง + ค่าบริการอื่น
- จำนวนวันนับรวมวันเริ่มและวันคืน (10–12 = 3 วัน)
- Backup: ตั้งค่า > Export JSON / CSV และ Import JSON กลับได้ (ฐานข้อมูลออนไลน์ยังเป็นข้อมูลหลัก)

## 🚚 การจัดส่งต่างจังหวัด (คำนวณวันส่งตามระยะทาง)
**ตั้งค่าครั้งแรก:** ตั้งค่า > การจัดส่งต่างจังหวัด
1. เลือก **จังหวัดที่ตั้งร้าน** (จำเป็น)
2. **กฎระยะทาง → วันส่ง + ค่าจัดส่ง** แก้เองได้ ค่าตั้งต้น: ตั้งแต่ 0 กม. = 1 วัน, ตั้งแต่ **1,000 กม. = 3 วัน** (เพิ่มขั้นได้ เช่น 500 กม. = 2 วัน) แต่ละขั้นใส่ **ค่าจัดส่ง (บาท)** ได้ในแถวเดียวกัน (0 = ไม่คิด)
3. (ไม่บังคับ) ตาราง **กำหนดรายจังหวัดเอง** ถ้าระยะ/วันที่ระบบคำนวณไม่ตรงความจริง กำหนดทับได้ทั้ง กม. / วัน / ค่าส่ง ช่องที่กรอกเองจะแสดงดอกจัน `*`
4. กด **บันทึก**

**ระบบคำนวณอย่างไร:** ระยะเส้นตรงระหว่างตัวเมืองของสองจังหวัด x ตัวคูณถนน (ค่าตั้งต้น 1.3) = ระยะทางโดยประมาณ เป็นค่าประมาณ ไม่ใช่ระยะ Google Maps จึงมีช่องกำหนดเองรายจังหวัดไว้

**ตอนสร้างรายการเช่า** เลือก "จัดส่งต่างจังหวัด" > เลือก **จังหวัดต้นทาง** (ค่าเริ่มต้น = จังหวัดร้าน เปลี่ยนได้ เช่น กรณีลูกค้าส่งต่อกันเอง) และ **จังหวัดปลายทาง** ระบบใส่จำนวนวัน **และค่าจัดส่ง** ให้ (แก้ในช่องได้เฉพาะรายการนั้น) แล้วแสดง:
- **ส่งของออกวันที่** = วันเริ่มเช่า - จำนวนวันส่ง
- **ของถึงร้านประมาณ** = วันคืน + จำนวนวันส่ง
- กล้องถูก **กันคิวตั้งแต่วันส่งออก ถึงวันที่ของคืนถึงร้าน** (ทั้งในหน้าเว็บและ trigger ที่ฐานข้อมูล) ปฏิทินก็แสดงตามช่วงนี้

> ค่า "กำหนดรายจังหวัดเอง" ตั้งเทียบกับจังหวัดร้าน จึงใช้เฉพาะเมื่อต้นทาง = จังหวัดร้าน ถ้าเลือกต้นทางอื่น ระบบคำนวณจากระยะทางและขั้นราคาล้วน ๆ
> ขาคืนใช้จำนวนวันเท่าขาไป (ต้นทาง↔ปลายทาง) แก้เองได้ในช่อง

> สำหรับงานจัดส่ง **"วันคืน" = วันที่ลูกค้าต้องส่งพัสดุกลับ** ค่าเช่ายังนับตามวันเริ่ม-วันคืนเหมือนเดิม ไม่รวมวันขนส่ง (ถ้าจะคิดเงินเพิ่ม ใส่ในค่าบริการอื่น)
> ผลคำนวณถูกบันทึกไว้ในรายการ ถ้าภายหลังแก้กฎ รายการเก่าไม่เปลี่ยน

## ✏️ แก้ไขรายการเช่า
เปิดรายการ > ปุ่ม **✏️ แก้ไข** แก้ได้ทั้งลูกค้า วันที่ ประเภท/จังหวัด กล้อง ส่วนลด ค่าส่ง มัดจำ หมายเหตุ ไม่ต้องยกเลิกแล้วสร้างใหม่
- แก้ได้เฉพาะสถานะ จอง / กำลังเตรียม / เตรียมแล้ว / เช่าอยู่
- ตรวจคิวชนซ้ำที่ฐานข้อมูล (ไม่นับตัวเอง) ถ้าชนจะไม่บันทึกอะไรเลย
- **รายการรับเงิน** และ **ค่าปรับ** ที่บันทึกไว้ไม่ถูกแตะ ยอดรวมใหม่นับค่าปรับเดิมต่อ
- กล้องที่มีอยู่เดิมคงราคา/วันเดิมที่ตกลงไว้ กล้องที่เพิ่มใหม่ใช้ราคาปัจจุบัน
- แก้มัดจำได้เฉพาะที่ยังไม่คืน/ไม่หัก
- เปลี่ยนจังหวัดในรายการ = คำนวณวันส่งและค่าส่งใหม่ตามจังหวัดนั้น (ไม่เปลี่ยนจังหวัด = คงค่าที่บันทึกไว้)

## 🙈 ซ่อนรายการ (แทนการลบถาวร)
รายการที่ยกเลิกแล้วมีปุ่ม **🙈 ซ่อนรายการนี้** ข้อมูลไม่ถูกลบ ยอดรับเงินและมัดจำยังอยู่ในฐานข้อมูล/Backup ครบ
ติ๊ก **แสดงรายการที่ซ่อนไว้** ที่หน้ารายการเช่าเพื่อดู และกด **↩️ แสดงรายการกลับ** ได้ หน้าอื่น (แดชบอร์ด รายงาน ปฏิทิน ฯลฯ) ไม่แสดงรายการที่ซ่อน

## ถ้าเจอปัญหา
- เปิดแล้วหน้าขาว: ต้องเปิดผ่าน Live Server / GitHub Pages ไม่ใช่ดับเบิลคลิกไฟล์
- Login ไม่ได้: ตรวจว่าสร้าง user ใน Supabase แล้ว และ URL/key ใน `js/config.js` ถูกต้อง
- ข้อมูลไม่ขึ้น / error permission: ยังไม่ได้รัน `policies.sql` หรือยังไม่ได้ Login
- สร้าง/แก้ไขรายการเช่าไม่ได้ หรือรายการไม่ขึ้น / error เรื่อง `dest_province`, `ship_date`, `deleted_at` หรือ `update_rental`: ยังไม่ได้รัน `schema.sql` ซ้ำหลังอัปเดต (**อัปเดตครั้งนี้ต้องรันซ้ำ 1 ครั้ง**)
